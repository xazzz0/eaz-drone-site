# Original project write-up workflow

Use this for a real completed EAZ Drones job. This is an internal template, not a published case study. Do not add an unfinished template to the website or sitemap.

## Capture the facts privately

Record the job date, actual service, agreed deliverables, and what the customer needed. Keep the customer's email, invoice, access codes, private address, and original response records outside this public repository. Get permission to publish the selected photos, project description, location detail, customer name, and any quotation separately. Ownership of an image alone does not establish permission to disclose a customer's project.

## Draft the public page after permission

- Title: [actual service] for [approved project type] in [approved city].
- Opening: Explain the customer's verified need and what EAZ Drones delivered in two useful sentences.
- Scope: State the actual capture date or period, media delivered, and relevant access or scheduling constraint. Include counts only from the delivered work.
- Original examples: Select the strongest permitted photos. Write captions describing what is visible, not generic keyword lists. Mark before/after dates accurately and never create a comparison from unrelated jobs.
- Outcome: Explain how the imagery was used only when confirmed by the customer. If results are unknown, state only what was delivered. Do not infer sales, savings, damage findings, or faster completion.
- Next step: Link to the relevant service page and quote path.

For construction, distinguish one visit from recurring coverage. Do not claim repeat-visit consistency until multiple real visits exist. For real estate and rentals, do not infer increased bookings or sale price from photography delivery.

## Final review and publication

Andrew confirms the facts and permission scope. Remove all placeholders. Compress images, include dimensions and useful alt text, and check mobile layout. Give the page a distinct title and canonical URL, add a relevant service-page link and sitemap entry, and run the site checks. Prepare a separate review branch/PR; do not publish automatically.

Draft only, with the real project reference filled in before use:
